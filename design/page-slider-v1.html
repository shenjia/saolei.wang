核心设计决策（请确认）
  • 滑条换页 = 严格一页（张老师 2026-10-14 定）：拖到已加载窗口之外的页 → 松手立即加载固定一页（排行/录像/BV 榜 20 条、论坛 19 条）整表替换，绝不多拉、绝不 gap 补拉；拖到已加载窗口之内的页 → 平滑滚动定位，零请求。最近翻过的页留缓存（≤30 页），回跳零请求。DOM 恒定，翻多深都不膨胀。去掉防抖的代价：快速连拖可能并发多个请求——用请求序号作废在途响应（只认最后一次松手），真实实现配 AbortController 取消在途 fetch。
  • 递增批量：「加载更多」= 在当前窗口末尾追加，批量按整页取：20/页 → +20 → +40 → +80 → +100 封顶（4 页）；19/页 → +19 → +38 → +76 → +95；15/页（动态）→ +15 → +30 → +60 → +100。首击=一页，与首屏语义衔接；换页（窗口重置）后序列从头计。按钮直接标注本次批量。
  • 两者共存：加载更多扩窗（表格向下长），滑条拇指=当前浏览页、暗绿填充=已加载窗口跨度。右侧保留「剩余 N 条」。
  • 覆盖范围：排行榜、BV 收集榜（505 页）、进步榜、录像列表、论坛列表五处。评论区/动态等小列表只改批量序列、不加滑条。

实现注记（确认后落地）

  • 组件：新建 PageSlider.tsx（滑条）+ 五处 Feed 底部改 list_footer 两行结构；pointer events，松手立即加载（无防抖），在途请求 AbortController 取消 + 序号门槛只认最后一次。无 JS 时滑条隐藏、加载更多照常（渐进增强）。
  • 请求语义：换页 = 既有 /api/*/more?page=N 原样复用（每页固定 20/19 条，查询层零改动）；窗口内跳页滚动定位零请求；最近 30 页 LRU 缓存回跳零请求。「加载更多」批量按整页取（+20→+40→+80→+100 / 19 制→+95 / 15 制→+100），需 more 接口放宽 size 上限（50→100），一次性拉 [winEnd+1, winEnd+n] 各页（并发拉页模式站内已有先例）。
  • URL 不写 page：保持「URL 即筛选状态」现状，翻页为客户端状态（BV 榜 ?page= 深链落地兼容保留）；换页后滚动回表格顶部、加载更多保持原位。
  • 性能红线：单请求 ≤100 行；换页后 DOM 恒定 = 1 页 × 20 行；缓存 LRU ≤30 页；加载最多次连点后 DOM ≤ 100 行追加段 × n（与现状加载更多一致，用户主动行为）。
